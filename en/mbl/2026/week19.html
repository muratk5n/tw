The vibe coding interaction cycle with LLMs can involve some bug fixing, troubleshooting. On pure chat interaction, you describe task, LLM gives code, and one out of three times the code will give errors. You give the error to LLM, it can fix it, or another error can occur. The tech has some ability in these areas, they ingest the entire Internet where people talk about similar issues, so they can eventually land on a solution.

Now, these so-called agents simply automate said interaction. Via agents user describes task and a verifiable goal, now "the agent" will talk to LLM, run the code it outputs (this is critical, you have to give access to your own machine so LLM can run stuff), it takes errors if any, feed it back to LLM, and do this until there is working code. Basically it replicates what users do on their pure chats, introduces some automation on top.

In other words "agents" are not an extension, the next iteration of LLM tech, they are a "wrap" around it. They try to cover a shortcoming with a little glue and silly putty.
